## 2. 鉴权

先 `GET /auth/config`（不鉴权）决定方式。回包：`provider, issuer, client_id, authorization_endpoint, token_endpoint, end_session_endpoint, scope`。404 当 local。

### local（邮箱 + 密码）
`POST /auth/login {email, password, device}` → `{token, user}`；存令牌 → rearm → `GET /auth/me`。

### oidc（Casdoor，授权码 + PKCE S256，公开客户端）
1. 校验端点：issuer 与各端点必须 https（回环地址可 http），端点 origin == issuer origin，不得带 userinfo。
2. verifier = base64url(32 随机字节)；challenge = base64url(sha256(verifier))；state = base64url(16 随机字节)。
3. 授权参数：`client_id, response_type=code, redirect_uri=umbra://auth/callback, scope(默认 "openid profile email"), state, code_challenge, code_challenge_method=S256`。
4. 回调 scheme `umbra` host `auth` path `/callback`，state 一致且非空。Android 用 Custom Tabs 打开 + intent-filter 收回调。
5. 换令牌：表单 POST token_endpoint，`grant_type=authorization_code&client_id&code&redirect_uri&code_verifier`，`Accept: application/json`。
6. 刷新：`grant_type=refresh_token&client_id&refresh_token&scope`。表单编码只保留 `A-Za-z0-9-._~`。
7. 这两类请求不走统一出口，单独客户端，超时 20 秒。
8. `access_token` 当会话令牌存；`refresh_token` 与签发它的 IdP 配置（`issuer, client_id, token_endpoint, scope`）一起存。续期只用存下的那份配置。
9. IdP 5xx / 网络不通 = 「连不上」，不是「拒了」。

### 令牌存储
iOS 钥匙串 `session-token` / `oidc-refresh-token` / `oidc-client`。Android：Keystore AES-GCM 包裹后存 DataStore（`SecureStore`）。
清会话令牌时三样一起清。每次真读，不做内存缓存。

### 请求头
只有 `Authorization: Bearer <token>`，JSON 带 `Content-Type: application/json`。**不要再带 `X-Umbra-Token`**（2026-10-14 已删）。
「人引起的请求」：最后一次真实触摸 / 键盘输入在 3 秒内且非后台路径 → `X-Umbra-Initiator: user`。同步、轮询、重连补拉、续期、启动问门一律不带。

### 失效判定（统一出口）
- 分档看响应头 `X-Umbra-Error`，**不看 detail 文案**；头没有再看 body 的 `code`。
- 会话失效：401 + `X-Umbra-Error: session_invalid`；或任意状态码下 `X-Umbra-Session: invalid`（trim、忽略大小写）。
- 401 + `unauthorized` / `bad_token` / 空 → badToken，**不登出**。
- `/auth/*` 分档：401 `bad_credentials`=密码错；401/429 `too_many_attempts`+`Retry-After`=锁 N 秒；400 `invalid_field`+`field=invite`=邀请码错；503 且 detail 含「发信」=发信未配；其他 503=账号功能未启用；400/404/409=rejected；其余 other。

### 失效处理（唯一入口 `SessionRevoke.report(sentSession)`）
1. 闩：发请求时带的令牌非空、等于本机当前令牌、闩未合 → 才处理。
2. OIDC 且有刷新令牌 → 静默续期一次；并发共用一次在途续期；冷却 30 秒（刚续上 30 秒又被拒直接登出；IdP 连不上后 30 秒内的信号忽略）。
3. 续不上 → 清令牌、标 sessionInvalid、长连接 halted、弹一次「登录已失效」。重新登录后 rearm。

### 登出
`DELETE /push/.../register`（有推送时）→ `POST /auth/logout`（失败不管）→ 清本机令牌 → `.out`。

### refresh()
无令牌 `.out`；`/auth/me` 成功 `.signedIn(user, devices)`；断网 / 解析失败**保持原状态**；await 回来核对令牌没被换过。

### 登录门
| 本机状态 | 结果 |
|---|---|
| 有令牌、/auth/me 成功 | open |
| 令牌失效 | sessionInvalid |
| 有令牌但服务器不通 | open |
| 无令牌、provider=oidc | login |
| 无令牌、`GET /auth/invite-required` → `{invite_required, invite_kind}` | true→login，false→register |

刚手动登出过的，即使问出 open 也落登录屏。

### 单机模式 / 会话守卫
- 「先单机使用」：不再主动弹登录屏，守卫仍是未登录；sessionInvalid 不管单机都弹。单机默认落在提醒 Tab。
- **本地功能**（未登录可用、登出不关）：提醒（通知/角标/小组件）、保险箱（含自动填充）、常用语、记账生活账本与周期规则、灵感（本机账本）、连接/通知/通用/关于、账号页。
- **要登录**：聊天、任务、知识库、设备与能力、记忆、执勤、商城、存储、改密码、会话列表、注销、经营账本。
- 守卫在进出「未登录」时统一执行各联网功能登记的关/开（提醒同步、任务小组件、推送令牌、长连接）。先写 signedOut 标记再逐项执行；第一次定下状态一律执行一次。
- 请求闸（出口第一行）：未登录只放行 `/auth/*` 与 `/health`；含 `.`/`..` 段一律不放；先去掉服务器地址自带路径前缀；拦下抛本地错 `SignedOutRequestBlocked`（不记离线、不当 401）。

## 4. WebSocket `/ws/chat`

- 鉴权只靠查询串 `session=`。
- 服务端握手：accept →（失效）发 `{"type":"session_invalid"}` 再 4001/`session_invalid` 关 →（闸不过）4001 空 reason → 补发未答 `question_card`、`confirm_request` → `{"type":"ws_ready"}`。
- 客户端状态：connecting / online / offline / unauthorized。**101 只算连接中，见 `ws_ready` 才在线**，退避归 1。
  老服务端不发 ws_ready：首颗 pong 后再等 2 秒没被关算认了；本进程见过该服务端发 ws_ready 后不再走退回规则。
- 关闭：4001+`session_invalid` → 失效入口；其他 4001 → unauthorized 不重连；其余 → offline，退避 1/2/4… 封顶 30 秒。失效或未登录不重连。
- 心跳：前台每 30 秒一颗 ping（**文本帧**，服务端 `receive_text`，二进制帧会被断），连续 2 颗没回断开重连；回前台立即发一颗只发不判死。
- 断线回调会接连到达，要过滤非当前连接的事件。

## 5. 核心模型

- **HistoryMessage**：id, role, content, created_at?, conversation?, kind?, atts?, meta?（interrupted, cancelled, quote, tools, action, task_id, citations 宽松解码, duty, duty_notice）
- **ConversationRow**：conversation, last_role, last_content, last_at?, count
- **TaskItem**：id, name?, goal, status, result_summary?, channel?, created_at?, updated_at?, steps_total?, steps_done?, executor?（`operate`=电脑操作）；挂起：suspend_reason, missing_capabilities, missing_capability_labels（元素可 null）, waiting_devices, suspended_step, resume_ready, ready_reason。标题 name 优先。
- **TaskDetail**：task, steps[TaskStep{id, seq, title?, status, detail?, device_id?, elapsed_ms?, error{kind,message,detail,reason_kind,topup_url}?, result_json?}], events[TaskEvent{id, type, message?, step_id?, payload, created_at?}]
- **KnownDevice**：device_id, device_name, platform, online, last_seen?, providers[ProviderInfo{provider, display_name, kind, available, unavailable_reason, version?, skills[{name,description}], unavailable_text?, features{control,unattended,files,clipboard}?, displays[{id(串或数), name, primary, width, height}]?}]
- **ReminderDTO**：id, text, note, at_ms, repeat_rule, custom_freq, custom_n, repeat_end_ms?, ahead_minutes, done, source, tz, updated_at_ms, deleted, atts[{file_id,label}]?, created_at?, anchor_day?, week_days?
- **Inspiration**：id, raw, title, summary, tags, status, source_channel, created_at, updated_at, organize_status, research, research_status, research_at, uid, updated_at_ms, atts
- **MoneyEntryDTO**：id(客户端生成), cents, direction, cat, sub, merchant, at_ms, tz_offset_min, ym, src, rule_id, batch_id, order_no, updated_at_ms, deleted, atts, invoice_no, invoice_kind, receipt_state, tax_rate_bp, net_cents, deduct_tier, is_asset
- **Phrase**：id, name, content, keyword, order, updatedAt, orderUpdatedAt（驼峰）

## 6. 深链 `umbra://`

| 链接 | 目标 |
|---|---|
| `umbra://tasks` / `umbra://task/<id>` | 任务列表 / 详情（id 不合法落列表） |
| `umbra://reminders` / `umbra://reminder/<id>` | 提醒列表 / 详情 |
| `umbra://money/add` / `umbra://money` | 记一笔 / 记账首页 |
| `umbra://auth/callback` | OIDC 回调 |
id 只认 `[A-Za-z0-9_-]{1,64}`。已登录直接跳；门未定先攥着；未登录只扔掉要登录的目标，登录后不补跳。

## 7. 推送

iOS：`POST /push/apns/register {token, env}`，payload `{"aps":{…,"thread-id":"duty"},"message_id","conversation":"assistant"}`。
**Android 需要服务端补**：`/push/fcm/register`（或泛化带 platform）、放宽令牌校验（FCM 令牌含 `: - _`）、FCM 发送器（data 消息，message_id / conversation 放 data）、令牌表。
国内设备没有 GMS 时 FCM 不可用，需厂商通道（华为/小米/OPPO/vivo/荣耀）或统一推送联盟 —— **一期不做**，Android 先靠前台 WS + 本地通知。提醒是本机定时通知，不依赖推送。

## 8. 对 Android 同样适用的坑

1. 关 HTTP 缓存（OkHttp 默认不缓存，别加 Cache）。
2. 跨源 3xx 不跟；只允许同主机 http→https。OkHttp 设 `followRedirects(false)` 自己判。
3. URL 里的值用 encodeURIComponent 档；`+` 会被当空格。路径段 id、发票号都要编码。
4. 「没拉到」= null，「空」= []，不许混。
5. 分档只看 `X-Umbra-Error` → body `code`，不看 detail。
6. 不是每个 401 都登出。
7. 失效信号与**发请求时带的令牌**比。
8. 刷新令牌只能一次在途，30 秒冷却；IdP 连不上不登出；后台进程不许清刷新令牌。
9. 清令牌连带刷新令牌与 IdP 配置；续期只用登录时存的配置。
10. `/auth/config` 端点要校验。
11. AuthUser 宽松解码。
12. WS：等 `ws_ready`；4001 不重连；只发文本帧；过滤旧连接回调。
13. 补发的卡按 card_id / confirm_id 去重；本地已处理但服务端还在补发 → 复位卡。chat_message 按 id 去重。
14. 用户消息由 `user_message_id` / message_saved 认领 id。
15. multipart filename 洗字符；转码后改后缀。
16. `ledger=` 由统一出口附加。
17. storage_full 在 413 兜底之前识别。
18. 商城订单两种回包形状都认。
19. 知识库删除无 sha 不发。
20. 打标宁可少标。
21. 图片档位以 `GET /settings` 的 `image_tiers` 为准，键 `image.quality.<chat|money|reminder>`。
22. 换账号 / 换服务器时本机待推数据先问用户（带过去 / 丢掉 / 以后再说），比较时连服务器地址一起比。

## 9. 需要服务端配合的（Android 专属）

- WS / 统计的 `src=android`、`client_kind="android"` 是否被服务端接受 —— 实现时先查 `routes/ws_chat.py`。
- FCM / 厂商推送注册接口（§7）。
- 远程控制 `rc_request.client_kind` 允许 `android`。
